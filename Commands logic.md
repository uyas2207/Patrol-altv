## Команды 
### Path
1. debug
   Включает глобальный debug для всех игроков на сервере (сервер запоминает состояние глобального debug). Глобальный дебаг визуализирует всю информацию которая есть на клиенте:
	   1. область видимости всех ped которые были созданы на клиенте через gameEntityCreate
	   2. Все маршруты (маркеры с цифрами показывают номер ноды, последовательно соединяет соседние ноды линями что бы показать от какой ноды к какой будет двигаться ped) которые есть на клиенте (были получены через команду load)
	   3. + Не отображает маршруты (защита от двойного отображения одной и той же визуализации) и область видимости ped которые отображаются с помощью ped debug (визуализация ped и его маршрута если такой назначен) 
2. addnode
   Проверяет на корректность значение ноды (нода может быть только целым числом от 0 до 9, что бы проще было визуализировать маркеры с номером ноды + вряд ли понадобятся маршруты больше чем из 9 точек).
   После этого передает данные для ноды на клиент: номер ноды, координаты на которых стоит игрок (координаты на которых будет находится нода) и точка в 5 метрах по направлению взгляда игрока (место на которое будет смотреть ped стоя на этой ноде).
   Клиент проверяет существует ли нода с таким id в списке нод текущего маршрута (если существует return) + существует ли текущий маршрут. Добавляет ноду с полученными данными в текущий маршрут, после этого пересортировывает все ноды в маршруте что бы они шли от меньшего node_id к большему 
3. dellnode
   Проверяет на корректность значение ноды (нода может быть только целым числом от 0 до 9, что бы проще было визуализировать маркеры с номером ноды + вряд ли понадобятся маршруты больше чем из 9 точек). После этого передает данные для ноды на клиент: номер ноды.
   Клиент проверяет есть ли нода с таким node_id в списке нод текущего маршртуа, если есть удаляет ее.
4. clear
   Сразу передает на клиент. Клиент полностью очищает текущий маршрут и его атрибуты (id, name, looped, asigned, isdebuged), проверяет был ли ped которому назначен такой маршрут, если есть такой ped отменяет маршрут и изменяет значение назначенного ped маршрута на null.
5. save
   Сразу передает на клиент. Клиент проверяет существует ли текущий маршрут, если да сохраняет все необходимые данные (id, name, looped, nodes) в один объект и передает для сохранения на сервер.
   Сервер заменяет в объекте routeData (общий список всех routes полученных при инициализации класса из файла routePoints.json) route с таким же name как и name маршрута полученного с клиента на полный список значений полученных с клиента. После этого перезаписывает все данные из объекта routeData в файл routePoints.json.
6. load
   Проверяет на корректность значение routeName введенного вместе с командой (существует ли в routeData routeName введенный в команде), после успешной проверки отправляет на клиент все значения этого route (id, name, looped, nodes).
   Клиент проверяет существует ли у него в mainMap route с таким же id, если нет запоминает его в currentRouteAttributes (id, name, looped, asigned, isdebuged) и в currentRouteMap (nodes и их значения index, position, rotation, waitTime), после чего добавляются все эти значения в mainMap в формате attributes и nodes.
7. create
   Проверяет не существует ли в routeData (общий список всех routes полученных при инициализации класса из файла routePoints.json) route с таким же name как в команде. Если маршрута с таким же названием нет добавляет в routeData новый route с параметрами: id последнего route +1, название как в команде, looped=false и пустой массив nodes. После этого перезаписывает в файл routePoints.json значением routeData с новым пустым route. Передает на клиент все данные нового route (id, name, looped, и пустой массив nodes).
   На клиенте происходит все то же самое что и в случае с командой load. 

Доп команды:

8. info (debug команда)
   Сервер сразу передает команду на клиент.
   Клиент выводит всю информацию которая хранится в классе RouteManager:
	   1. mainMap - map в котором хранятся все маршруты когда либо переданные на клиент и их доп атрибуты
	   2. currentRouteMap - map в котором хранится только один маршрут, маршрут к которому присоединяют/удаляют ноды командами addnode/dellnode 
	   3. currentRouteAttributes - доп атрибуты маршрута из currentRouteMap (id, name, looped, asigned, isdebuged)
9. switch - команда которая позволяет менять маршрут к которому добавляются/удаляются ноды (без нее все ноды добавлялись/удалялись у последнего переданного на клиент маршрута и не было возможности добавить ноды в другие маршруты)
   
   Сервер проверяет существует ли route с параметром name как в команде, если существует то передает на клиент routeID маршрута с таким name (так как на клиенте в мапе маршрутов кличем является routeID)
   На клиенте проверяется существует ли на клиенте маршрут с таким routeID, если существует просидит перезапись всех данных текущего маршрута и его атрибутов (currentRouteMap, currentRouteAttributes) и в mainMap под соответствующим ключом присваиваются ссылки на новые данные currentRouteMap, currentRouteAttributes, поэтому после изменений они будут отображаться в mainMap под корректным ключом (правильным routeID)

### Ped
1. asign
   На сервере проверяет существует ли ped с указанным в команде pedid, проверяет существует ли route с указанным в команде name. После успешной проверки передает pedid и route.id (так как на клиенте в мапе маршрутов кличем является routeID) на клиент.
   На клиенте проверяет загружен ли на клиент route с переданным routeid, инициализировался ли когда либо на клиенте ped с переданным pedid. После успешной проверки назначает ped текущий маршрут (currentRouteMap) с помощью нативок, проверяет всех других ped на то что им назначен такой же маршрут и если назначен отменяет его и записывает все необходимые данные в соответствующие map (какому ped назначен маршрут в mainPedMap: asignedRoute, у конкретного ped имеется ли назначенный маршрут true/false currentRouteAttributes: asigned) 
2. debug
   Сервер проверяет существует ли pedid указанный в команде и передает его на клиент
   На клиенте проверяет инициализировался ли когда либо на клиенте ped с переданным pedid. Проверяет включен ли у ped с переданным id debug, если нет включает, если да выключает.
   Включение debug:
	   Запускает everyTick в котором рисуется visioncone ped и если есть назначенный ped маршрут визуализирует его nodes и соединяет соседние nodes линиями
	   Изменяет необходимые данные mainPedMap: isdebuged и если у ped есть назначенный маршрут mainMap: isdebuged
	   Так как у нескольких ped может быть включен одновременно debug хранит в map singleDebug под ключом ped.entity.id его everyTick
   Выключение debug:
	   Очищает everyTick в котором рисуется debug 
	   Изменяет необходимые данные mainPedMap: isdebuged и если у ped есть назначенный маршрут mainMap: isdebuged
	   Удаляет по ключу pedID из map singleDebug, так как у ped больше нет debug который помнить для очистки
3. stop
   Сервер проверяет существует ли pedid указанный в команде и передает его на клиент
   На клиенте ищет в mainPedMap pedid, проверяет есть ли у ped asignedRoute и если есть останавливает патрулирование и изменяет все необходимые данные:
	   какому ped назначен маршрут в mainMap: asigned
	   если ped в debug mainMap: isdebuged так как маршруту больше не будет отображаться в peddebug
	   mainPedMap: asignedRoute

Доп команды: 

4. info (debug команда)
   Сервер проверяет существует ли pedid указанный в команде и передает его на клиент
   На клиенте выводит всю информацию об entity ped (netOwner, scriptID, entity id, и всю остальную существующую информацию)
5. map (debug команда)
   Сразу передает на клиент команду
   Клиент выводит всю информацию которая на данный момент записана в map mainPedMap для каждого ped (entity, asignedRoute, isdebuged)
