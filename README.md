## Сервер

Общий (global) debug хранится на сервере и отображается для всех игроков на сервере одновременно. Global debug показывает область видимости всех ped и все route загруженные у клиента (у каждого клиента могут быть загружены разные route).
#### **Классы**:
##### 1. PatrolServer
   основной класс, инициализирует другие классы и передает им необходимую информацию (например расположение файла с маршрутами)
##### 2. PatrolCommands
обрабатывает команды которые прописывает игрок и передает их в соответствующие классы для их выполнения или сразу передает на клиент всю необходимую информацию. Все команды записаны в объекте this.commands
##### 3. PedManager
   Создает ped в соответствии с конфигом и проверяет команды для ped на то что они обращаются к существующему ped
##### 4. Debug
   Запоминает состояние общего (global) debug и включает/выключает по команде. 
##### 5. RouteStorage
Отвечает за работу с фалом в котором хранятся все routes. При инициализации класса запоминает все данные которые хранятся в файле с routes. По команде передает один из routes на клиент (load). По команде создает новый route в изначальный файле с routes. По команде сохраняет route переданный с клиента в изначальный файл с routes.
## Клиент
Все данные хранятся на клиенте, что бы сервер не занимался подсчетами координат и данных для отображение debug, из-за этого после перезахода на сервер все несохраненные данные с помощью команды save будут потеряны и придется заново загружать и назначать все маршруты.
#### **Классы**:
##### 1. PatrolClient
   основной класс клиента создает другие классы и передает им необходимую информацию (например данные из конфига). Реагирует на все emit с сервера и передает их в соответствующие классы.
##### 2. DebugManager
Отвечает за глобальный debug, хранит в себе everytick для глобального debug, включает и выключает global debug по команде с сервера. Передает в класс с визуализацией debug (debugVisuals) всю необходимую информацию для отображения (запрашивает эту информацию из других классов с помощью callback)
##### 3. DebugVisuals
   Отвечает за визуальное отображение debug область видимости ped, точки nodes. Получает данные которые нужны для отображения (nodes, pedPos, pedScriptID ...) и отображает. + рассчитывает с помощью координат игрока, координат ped и heading ped находится ли игрок в области видимости ped.
##### 4. PedManager
   Класс который хранит в себе всю необходимую информацию о ped (Ped, asignedRoute, isdebuged). Назначает маршруты ped, переназначает маршруты при перезалете в стрим зону, останавливает ped по команде с сервера + передает данные для изменения в класс RouteManager (например данные какому ped назначен маршрут и отображается ли маршрут в singledebug у ped).
##### 5. PedDebugManager
   Отвечает за хранение everytick для визуального отображения debug у конкретных ped, включает и отключает отображение debug у конкретного ped по команде с сервера.
##### 6. RouteManager
   Класс который хранит в себе всю информации о routes, общий список в mainMap и данные о текущем route в currentRouteMap + currentRouteAttributes (текущий маршрут - маршрут к которому будут добавляться/удаляться ноды по команде addnode/dellnode). Получает routes с сервера, передает routes на сервер по команде save, добавляет ноды к route, удаляет ноды из route.
